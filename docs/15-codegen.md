# 15 · Codegen：YAML → 静态调度图（v0）

**状态**：已实现（W4，2026-11-10）｜ **新增测试**：9 个｜ **累计**：40 个 host 测试全绿

> 本文是 `tools/codegen` 的实现契约。
> 上游背景：DoraOS 的 "一份 YAML，两个 target"；EchoOS 负责 Micro 侧的目标 API 与生成物。
> 相关：[11-arch-and-sched](11-arch-and-sched.md)、[14-pal-contract](14-pal-contract.md)。

## 1. YAML 输入（受限子集）

```yaml
# 3 节点静态数据流：sensor → control → actuator
frame_ns: 1000
nodes:
  - name: sensor
    slot_ns: 200
  - name: control
    slot_ns: 100
    inputs: [sensor]
  - name: actuator
    slot_ns: 50
    inputs: [control]
```

**这不是通用 YAML 解析器**，只支持：

| 语法 | 支持 |
| --- | --- |
| `#` 行内注释 | ✅ |
| `frame_ns: <u64>` | ✅ |
| `nodes:` + `- name: <str>` | ✅ |
| `slot_ns: <u64>` | ✅ |
| `inputs: [a, b]`（内联列表） | ✅ |
| 锚点/多行/嵌套映射/引号转义 | ❌ |

## 2. 校验规则

| 规则 | 失败 |
| --- | --- |
| `frame_ns > 0` | 报错 |
| 至少 1 个节点 | 报错 |
| 节点名非空且唯一 | 报错 |
| 每个节点有 `slot_ns > 0` | 报错 |
| `Σ slot_ns ≤ frame_ns` | 报错并给出和 |
| `inputs` 只能指向**更早**的节点 | 报错 `unknown or forward` |

**YAML 顺序就是调度顺序**。codegen 不做拓扑重排——静态图的可分析性来自"所见即所得"。

## 3. 生成物

`dataflows/three_node.yaml` 生成：

```rust
// @generated by tools/codegen from dataflows/three_node.yaml. Do not edit.

pub const FRAME_NS: u64 = 1000;
pub const NODE_COUNT: usize = 3;
pub const NODE_NAMES: [&str; NODE_COUNT] = ["sensor", "control", "actuator"];
pub const NODE_SLOTS_NS: [u64; NODE_COUNT] = [200, 100, 50];
pub const EDGES: [(&str, &str); 2] = [
    ("sensor", "control"),
    ("control", "actuator"),
];

pub fn task_defs(entries: [fn(); NODE_COUNT]) -> [echo_sched::TaskDef; NODE_COUNT] {
    [
        echo_sched::TaskDef::new(NODE_NAMES[0], NODE_SLOTS_NS[0], entries[0]),
        // ...
    ]
}
```

**codegen 只生成声明，不生成任务体**：

- 调度表、节点名、槽位预算、边元数据由 YAML 决定；
- 任务入口由应用注入（`entries`），避免把业务逻辑塞进生成器；
- `EDGES` 目前是元数据，通道/邮箱的自动接线在后续里程碑接入 PAL Channel 域。

## 4. 再生成与防漂移

生成物**检查进版本库**（可审计、可 diff、便于认证追溯）。

```bash
cargo run -p echo-codegen -- \
  dataflows/three_node.yaml \
  dataflows/generated/three_node.rs
```

`tools/codegen` 的 `checked_in_conformance_file_is_current` 测试会重新生成并逐字节对比；
**生成物与 YAML 不一致时 CI 直接失败**。

## 6. 决策

| # | 决策 | 理由 |
| --- | --- | --- |
| D-013 | YAML 顺序 = 调度顺序，不做拓扑重排 | 静态图的可分析性优先；重排会让调试与认证变复杂 |
| D-014 | 生成物 check in + 漂移测试 | 可审计、可 diff、CI 可守；与 `svdgen` 同一策略 |
| D-015 | 只生成声明，不生成任务体 | 业务逻辑归应用；生成器保持小、可测、可审查 |
| D-016 | 自写 YAML 子集解析，不引第三方 crate | 与 L1 一致；host 工具也不扩张依赖面 |

## 7. 明确限制

- ❌ 不做 DAG 重排 / 并行槽位 / 多帧速率；
- ❌ 不生成任务体、不自动接线 Mailbox；
- ❌ 不支持通用 YAML（锚点、嵌套、多行）；
- ❌ 还没有 `xtask codegen` 批量入口；
- ❌ 还没有 QEMU target 的生成（W5 再接）。
