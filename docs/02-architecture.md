# 02 · 总体架构

## 2.1 分层模型

```
┌──────────────────────────────────────────────────────────────────┐
│ L7  应用              apps/ / examples/                          │  用户任务
├──────────────────────────────────────────────────────────────────┤
│ L6  服务              echo-fs  echo-net  echo-shell  echo-ota    │  可裁剪
├──────────────────────────────────────────────────────────────────┤
│ L5  设备              echo-driver  echo-hal                      │  驱动模型
├──────────────────────────────────────────────────────────────────┤
│ L4  内核 API          echo-sys   echo-rt   echo-prelude    ← 对外稳定接口
├──────────────────────────────────────────────────────────────────┤
│ L3  内核子系统        echo-sched  echo-sync  echo-ipc            │
│                       echo-time   echo-mm    echo-critical       │
├──────────────────────────────────────────────────────────────────┤
│ L2  内核核心          Kernel<A> · TCB · 就绪队列 · 上下文切换      │  unsafe 集中区
├──────────────────────────────────────────────────────────────────┤
│ L1  体系结构抽象      echo-arch-api  (trait Arch)                 │  零硬件依赖
├──────────────────────────────────────────────────────────────────┤
│ L1' 体系结构实现      echo-arch-cortex-m │ echo-arch-riscv │ mock │  唯一汇编所在
├──────────────────────────────────────────────────────────────────┤
│ L0  硬件              Cortex-M0+/M3/M4/M7/M33 │ RV32IMAC │ x86(测试) │
└──────────────────────────────────────────────────────────────────┘
```

**依赖方向严格向下（L1' 除外，见 §2.3）。** L1 是抽象，L1' 是实现，二者同层但互不依赖——内核只认 L1。

## 2.2 内核形态：组件化宏内核

### 三种候选

| 形态 | 隔离 | IPC 开销 | 上下文切换开销 | MCU 适配度 |
| --- | --- | --- | --- | --- |
| 微内核（Tock 式） | 强（MPU 每进程） | 高（跨地址空间） | 高（含 MPU 重编程） | 差 |
| 单体内核（FreeRTOS 式） | 弱（无隔离或粗粒度） | 低（函数调用） | 低 | 好 |
| **组件化宏内核（EchoOS）** | **中（类型系统 + MPU 静态分区）** | **低** | **低** | **好** |

### 选择：组件化宏内核

理由：

1. **MCU 上隔离的性价比曲线很差。** 在 100 MHz Cortex-M4 上，一次 MPU 重编程约需数百纳秒到微秒级。若每次上下文切换都重编程，开销占比将超过 30%（Tock 延迟 15.6 µs vs RTIC 4 µs 的差距主要源于此）。
2. **Rust 已经免费提供了大量隔离。** 数据竞争、悬垂指针、所有权重复释放、跨线程共享可变状态——这些在 C 的 RTOS 里需要 MPU 运行时捕获的错误，在 Rust 里是**编译错误**。把隔离前移，MPU 就不需要在热路径上工作。
3. **子系统之间的接口是类型化的函数调用**，不是消息传递。不需要序列化、不需要拷贝、不需要跨地址空间跳转。

### 但保留"组件化"的含义

- 每个子系统是独立 crate，通过 trait 接口通信，可编译期裁剪。
- 子系统内部状态**不对外暴露**，只能通过 API 访问——为将来某天把某个子系统移入独立地址空间留了余地。

### MPU 的使用方式：静态分区

```
MPU Region 布局（编译期固定，运行时不重编程）
┌────────────────────────────┬─────────┬──────────────────────────┐
│ Region 0  内核 .text/.rodata│ RO/X    │ 特权可读执行              │
│ Region 1  内核 .data/.bss   │ RW      │ 特权可读写；非特权不可见   │
│ Region 2  内核堆            │ RW      │ 特权可读写；非特权不可见   │
│ Region 3  任务 A 的栈       │ RW      │ 特权 RW（用于填充/检测）   │
│ Region 4  任务 B 的栈       │ RW      │  非特权任务只能访问自己的   │
│ Region 5  任务 C 的栈       │ RW      │  栈；越界触发 MemManage    │
│ Region 6  当前任务的栈守卫页 │ NoAccess│ 变化时仅改这一个 region    │
│ Region 7  外设 MMIO         │ RW      │ 按驱动能力分配             │
└────────────────────────────┴─────────┴──────────────────────────┘
```

**关键优化**：Region 0–5 在启动时配置一次即固定不变，只有"栈守卫页"这一个 region（或少数几个）在切换时更新，且**仅当切换到不同任务时才需要**。这把 MPU 开销从"每次切换的数百纳秒"压到接近零。

若目标 MCU 的 MPU region 数量不足（Cortex-M0+ 只有 8 个），则降级为：MPU 只保护内核数据 + 当前任务栈守卫，其余任务之间的隔离退化为"类型系统保证"。这是可接受的降级路径。

## 2.3 可移植性设计：内核泛型化 over `Arch`

这是本架构中最重要的一个决策。

### 两种候选路线

**路线 A：内核泛型化 over trait（选择）**

```rust
// echo-arch-api
pub trait Arch: Sized + 'static {
    type Interrupt;                       // 中断号类型（芯片相关）
    fn disable_interrupts() -> State;
    fn restore_interrupts(state: State);
    fn set_interrupt_priority_below(prio: Priority);  // BASEPRI 语义
    fn switch_context(from: *mut Ctx, to: *const Ctx); // 唯一汇编边界
    fn idle();
    fn now_ticks() -> u64;
    // ...
}

// echo-kernel
pub struct Kernel<A: Arch> {
    scheduler: Scheduler<A>,
    clock: Clock<A>,
    // ...
}
```

- ✅ 单态化 → **零运行时开销**，无虚表、无间接跳转
- ✅ 编译期类型检查完整
- ✅ **可用 `echo-arch-mock` 在 host 上跑内核逻辑的单元测试** ← 决定性优势
- ❌ 内核代码被泛型参数污染，可读性下降
- ❌ 编译时间随实例化数量增长（实际只有 1 个实例，可接受）

**路线 B：移植层反向调用内核（FreeRTOS 风格）**

arch 层提供 `PendSV_Handler` 等符号，通过 `extern "Rust"` 声明内核导出函数。

- ✅ 内核代码干净，无泛型
- ❌ **内核无法在 host 上测试**（强耦合到具体架构的汇编入口）
- ❌ 跨层调用是隐式的、链接期解析的，错误发现晚
- ❌ 分析工具无法追踪调用图

### 选择：A 为主，B 仅用于纯汇编边界

最终形态是混合的：

```
┌───────────────────────────────────────────────┐
│  echo-arch-cortex-m                           │
│                                               │
│   #[unsafe(naked)] PendSV() ──汇编──┐          │
│   #[unsafe(naked)] SVC()     ──汇编──┤          │
│   #[unsafe(naked)] SysTick() ──汇编──┤          │
│                                      ▼          │
│   extern "Rust" {                             │
│       fn echo_kernel_tick();      // 内核导出  │
│       fn echo_kernel_schedule();  // 内核导出  │
│   }                                           │
│                                               │
│   impl Arch for CortexM { ... }  ← 泛型接口    │
└───────────────────────────────────────────────┘
```

- **数据路径**（时钟读取、临界区、中断控制、内存屏障）走 `trait Arch` 泛型 → 可 mock、零开销。
- **纯汇编边界**（异常入口、上下文切换的栈操作）走 `extern "Rust"` 声明 → 无法泛型化，但范围极小（每个架构约 200–400 行汇编）。
- 内核导出的符号是**薄封装**，只转发到 `Kernel::<A>::instance()` 的对应方法，不含业务逻辑。

### 移植层必须提供的完整能力清单

定义一个架构被 EchoOS 支持，必须实现：

| 能力 | 说明 | Cortex-M 实现方式 |
| --- | --- | --- |
| 启动与向量表 | Reset 入口、异常向量、栈初始化 | 自研 `link.x` + `vector_table` |
| 上下文切换 | 保存/恢复寄存器组 | `PendSV` + MSP/PSP 双栈 |
| 特权切换 | 首次进入非特权任务 | `SVC` 或 `CONTROL` 寄存器 |
| 临界区 | 有界关中断 | `BASEPRI`（见 §2.5） |
| 中断控制 | 使能/禁止/挂起/优先级 | NVIC |
| 时钟源 | 单调计数 | `SysTick` 或通用定时器 + `DWT CYCCNT` |
| 内存屏障 | 编译器 + CPU 屏障 | `dmb` / `dsb` / `isb` |
| 内存保护 | region 编程 | MPU |
| 低功耗 | 空闲进入 | `wfi` / `wfe` |
| 原子操作 | 单核下的原子语义 | `echo-atomic`（自研；M3+ 用原生 CAS，M0/M0+ 用临界区模拟） |
| 寄存器访问 | 内部可变性与权限标记 | `echo-vcell`（自研，替代 `vcell`） |

## 2.4 并发模型：线程 + 中断，async 可选

### 决策

**内核调度基础是线程（preemptive threads），不是 async 任务。**

### 理由

1. **硬实时要求有界响应时间。** async 执行器是协作式的：一个任务不 `await`，整个执行器就被占住。虽然可以用"每任务一个执行器 + 优先级"来缓解，但那本质上是用 async 语法重新实现线程，且丢失了抢占。
2. **中断与 async 的交互不自然。** 中断无法 `await`。传统 RTOS 的"ISR 唤醒任务"模型有明确且可分析的语义。
3. **栈模型可分析。** 每个任务有独立栈，栈深度上界可静态分析（借助 `stack-usage` 类工具）。async 的共享栈 + 状态机大小难以直观估算——虽然编译器知道，但开发者难以审查。
4. **生态成熟度。** RTIC 用纯中断驱动 + SRP 达到 4 µs 延迟，Embassy 用 async 达到 10 µs——**在硬实时这个维度上，非 async 的方案不落后**。async 的优势在 I/O 密集的人体工学，不在延迟。

### 但仍然提供 async 适配层

`echo-async`（可选 crate）提供：

- 把阻塞式同步原语（Mutex/Semaphore/Queue）包装为 `Future` 的适配器
- 一个可选的、跑在专用任务上的 `embassy-executor` 兼容执行器
- **允许应用用 async 写业务逻辑，但调度仍是抢占式的**

面向的应用特征：网络协议处理、状态机、UART 多路复用等 I/O 密集场景。

### 任务与中断的协作模型

```
                    优先级高
                       ▲
   ┌───────────────────┴────────────────────┐
   │ 硬件中断（NVIC）                         │  ← 实时性最关键，上界由 NVIC 优先级决定
   │  · 极短，只做 ack / 搬运到缓冲区          │
   │  · 只允许调用 *_from_isr API             │
   └───────────────────┬────────────────────┘
                       │ 唤醒任务 / 置位事件
   ┌───────────────────▼────────────────────┐
   │ PendSV（最低优先级） 上下文切换           │  ← 不与任何中断竞争，保证中断延迟
   └───────────────────┬────────────────────┘
                       │
   ┌───────────────────▼────────────────────┐
   │ 任务上下文（优先级抢占 + 同优先级 RR）      │  ← 业务逻辑、阻塞调用
   └────────────────────────────────────────┘
                    优先级低
```

**要点**：把上下文切换放在最低优先级的 `PendSV` 中，是 Cortex-M 上的标准做法。这样**任何中断都能立即抢占即将发生的任务切换**，中断延迟不受调度器影响。

## 2.5 关键机制

### 2.5.1 临界区：`BASEPRI` 而非 `PRIMASK`

| 方案 | 机制 | 中断延迟影响 | 适用 |
| --- | --- | --- | --- |
| `PRIMASK`（`interrupt::free`） | 屏蔽**所有**中断 | 差：高优先级中断也被延迟 | 短临界区、简单 |
| **`BASEPRI`（选择）** | 屏蔽优先级 ≤ 阈值的中断 | **好：高优先级中断继续响应** | 内核默认 |
| 自旋锁 | 原子操作 | 单核下仍需关中断配合 | 多核预留 |

**规则**：

- 内核临界区默认使用 `BASEPRI` 屏蔽到"内核不与之共享数据的中断优先级之上"。即：**只有需要访问内核数据结构的中断（通常是驱动 ISR）会被屏蔽，其它高优先级中断照常响应。**
- 临界区长度是**审查项**：单个临界区不得包含循环、内存分配、任意函数调用。
- `echo-critical` 提供 `CriticalSection` RAII guard，封装恢复逻辑，防止遗漏。

```rust
let cs = echo_critical::enter();      // 进入：设置 BASEPRI
// ... 有界操作 ...
drop(cs);                             // 退出：恢复原 BASEPRI（RAII 保证）
```

### 2.5.2 上下文切换

**Cortex-M 实现**（`PendSV` + 双栈）：

- 任务栈用 PSP，内核/中断栈用 MSP。这天然实现了"中断不消耗任务栈"。
- 硬件在异常入口自动压栈 **8 个寄存器**（R0–R3、R12、LR、PC、xPSR），软件只需压栈剩余被调用者保存寄存器（R4–R11）。
- **分阶段实施**：
  - **M2 阶段**：全保存。若目标有 FPU，无条件保存 S0–S31（`CONTROL.FPCA` 开启 lazy stacking 时由硬件处理）。**正确性优先。**
  - **M5 之后优化**：按 `FPCA` 标志决定是否保存 FPU 寄存器，避免不用浮点的任务付出代价。

**新的任务首次运行**：伪造一个"刚从异常返回"的栈帧（xPSR 置 Thumb 位、PC 置入口地址、LR 置任务退出陷阱），然后 `bx` 到该帧——任务入口看起来像是从异常返回。

### 2.5.3 中断延迟的构成

```
中断到达 ─┬─► [硬件] 异常进入（12 周期，Cortex-M3/M4 尾链优化）
          ├─► [硬件] 自动压栈 8 寄存器
          ├─► [软件] ISR 入口保存剩余寄存器
          ├─► [软件] ISR 业务代码          ← 需要最短
          └─► [软件] 中断退出，触发 PendSV  ← 若需要调度
```

**优化手段**：

1. **尾链（tail-chaining）**：连续中断无需重新压栈，硬件自动优化。前提是 ISR 不破坏栈帧。
2. **迟到（late-arriving）**：更高优先级中断到达时硬件重新决策，不重复压栈。
3. **ISR 最小化**：ISR 只做 ack + 数据搬运 + 唤醒任务。**禁止在 ISR 中做任何可能长时间运行的操作**（打印、内存分配、Flash 写入）。
4. **不需要调度的中断不触发 PendSV**：只有 ISR 唤醒了更高优先级任务时才置 PendSV。

### 2.5.4 启动流程

```
Reset_Handler                         [汇编, echo-arch-*]
  │
  ├─ 1. 最小安全环境（Flash 等待周期、FPU 使能、看门狗）
  ├─ 2. 早期完整性自检（可选：.text CRC、RAM March-C）
  ├─ 3. 初始化 .data（从 Flash 拷到 RAM）/ 清零 .bss      [echo-rt]
  ├─ 4. 时钟树初始化（HSE/PLL → 目标主频）                [BSP]
  ├─ 5. 时钟节拍源初始化（SysTick 或通用定时器）
  ├─ 6. 堆初始化（若启用）                                [echo-mm]
  ├─ 7. 内核初始化                                        [echo-kernel]
  │     · 初始化就绪队列、MPU、休眠链表
  │     · 创建 idle 任务（最低优先级，跑 wfi）
  │     · 创建定时器服务任务
  ├─ 8. 静态创建用户任务（编译期注册的任务表）
  ├─ 9. 启动第一次调度 → 进入任务上下文，切换到最低优先级就绪任务
  └─ 10. （永不返回）
```

用户视角：

```rust
#[echo::main(stack = 2048, priority = 5)]
fn main() { /* ... */ }

#[echo::task(stack = 1024, priority = 3)]
fn sensor_task() -> ! { loop { /* ... */ } }
```

宏展开为 `static` 的 TCB 与栈数组，注册到 `.echo_tasks` 链接段，由启动流程遍历创建。**无运行时分配。**

### 2.5.5 实时性保证手段清单

| 手段 | 解决的问题 | 实现位置 |
| --- | --- | --- |
| 固定优先级抢占 | 高优先级任务的响应上界 | `echo-sched` |
| 优先级继承协议（PIP） | 无界优先级反转 | `echo-sync` |
| BASEPRI 临界区 | 关中断窗口过大 | `echo-critical` |
| Tickless 空闲 | 无谓 tick 中断 | `echo-time` |
| 确定性内存分配 | 分配时间不可预测 | `echo-mm`（内存池/TLSF，均 O(1)） |
| ISR 上半部/下半部 | ISR 过长 | `echo-driver` |
| 临界区审计 | 意外的长窗口 | 编译期扫描 + 运行时记录 |
| 延迟基准回归 | 性能退化不可见 | `echo-bench` + CI |

### 2.5.6 可配置性：编译期常量，不用 feature 组合

Cargo feature 用于"可裁剪"会导致**组合爆炸**：N 个 feature 有 2^N 种组合，CI 无法全测。

**EchoOS 方案**：

- **裁剪（要不要这个子系统）** → 用 Cargo feature，但**保持正交、扁平、低频**（每个服务 crate 一个 feature，如 `fs` / `net` / `shell`）。
- **参数（栈大小、优先级数、tick 频率、任务数）** → 用 `echo-config` 的编译期常量 + const 泛型，**不占 feature 维度**。

```rust
// echo-config —— 由 BSP 通过 build.rs 或直接 const 覆盖
pub const MAX_PRIORITIES: usize = 32;        // 优先级级数
pub const TICK_HZ: u32 = 1000;               // 节拍频率
pub const STACK_GUARD_SIZE: usize = 32;      // 栈守卫大小（字节）
pub const IDLE_STACK_SIZE: usize = 512;
```

裁剪矩阵（CI 必须覆盖）：

| 配置 | 用途 | feature |
| --- | --- | --- |
| `minimal` | 最小内核 | 无 |
| `standard` | 内核 + 驱动 + trace | `drivers`, `trace` |
| `full` | 全功能 | `drivers`, `trace`, `fs`, `net`, `shell` |
| `alloc` | 启用堆 | `alloc` |

4 种受测配置，而非 2^N。
